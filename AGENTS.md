## Architecture decisions
- Render uses `npm ci --include=dev && npm run build:render` and `npm start`: a single public Node gateway with private Nitro SSR and API bridge children. `/healthz` is server readiness; `/api/matlab/health` is real processor readiness. Production defaults to `MATLAB_MODE=disabled`, uses dashboard secrets rather than bridge/.env, and can connect to an authenticated HTTPS licensed bridge in remote mode. Never imply Runtime/Compiler or Linux processing has been tested without an actual artifact/runtime. Preserve the Lovable build target through ordinary `npm run build`.
- Keep the interactive image laboratory on the index route, following the porcelain/crimson reference with coral gradients, a serif wordmark, working navigation rail, prominent comparison canvas, right-hand histogram/tools, and full-width sequence strip. Use shared surface tokens across the studio, simulation, noise, and AI. Enhancement runs through the local Node bridge and persistent MATLAB worker; base MATLAB algorithms do not require Image Processing Toolbox. Run the complete local app with `npm run dev:full`.
- Keep LUMA AI visibly labeled and floating above the workspace, with a dedicated pointer/touch drag handle, keyboard repositioning, persisted viewport-clamped placement, and a panel Reset position action. Default to the safe lower-right corner; do not reserve a footer or launcher-sized blank band below the workspace. Status belongs inside its panel. Pointer lighting affects materials/frame edges only and is disabled for touch and reduced motion. Use actual histogram counts and real input/completed-output sequence thumbnails; never fabricate preset or intermediate processing images.
- Use the shared `{imageId, category, method, parameters}` processing route. Keep Intensity Transformations and Spatial Filtering distinct, validate relevant parameters at both bridge and MATLAB boundaries, and preserve the original. Stretch cutoffs are normalized input brightness values, not percentiles. Spatial smoothing/sharpening uses replicated boundaries and RGB luminance; Sobel produces a labeled grayscale edge map. Histograms/statistics must describe the actual returned image. Do not present browser previews as MATLAB results.
- Mean/Gaussian/Median/Unsharp accept all odd kernel sizes 3–15. Preserve sigma/strength when size changes, and validate size in the UI, bridge, and MATLAB. Sobel remains a fixed 3×3 operator. The step walkthrough uses real browser-decoded image luminance and replicated boundaries but must stay labeled as an illustrative local simulation; never use it for export or MATLAB statistics. Keep its state separate from main enhancement state.
- Processing Sequence snapshots up to six operations and sends `{imageId, steps, runId}` to the same endpoint. `apply_operation.m` dispatches both single operations and ordered in-memory sequences. Each step consumes the preceding output; retain the original separately. Progress comes from MATLAB via `write_job_progress.m`, not an estimated percentage. Never export a partial/failed/stale sequence. Reset preserves saved steps, clear removes them, and control edits resume the single-operation preview. Keep sequence execution separate from the illustrative simulation.

- Noise Playground uses the same MATLAB job queue and preserves the clean source. Seeded salt-and-pepper/Gaussian noise shares samples across RGB channels; Gaussian strength is normalized standard deviation, not variance. Register noisy PNGs as separate bounded temporary inputs and apply shared spatial filters to that noisy ID. Keep playground state separate from studio sequences, and export only the selected current actual output.
- Groq access stays in the Node bridge. Load secrets only from server environment or ignored bridge/.env; never use VITE_ variables, client credentials, logs or image transmission. Validate allowlisted processing metadata and distinguish draft settings, completed results, stale/failed states and measured statistics. AI is optional, has no processing mutation capability, and cannot block MATLAB. Keep model configurable without a fallback and errors free of provider payloads/secrets.

- Shared operation capabilities live in shared/operations.json and shared/operations.mjs. MATLAB reads the same registry and advertises only startup-probed implemented operations. Processing and AI recommendations validate against this registry, with all AI parameters explicit and no silent substitutions. Restart the backend for registry/implementation changes.
- Render AI text with safe react-markdown/remark-gfm, no raw HTML or images, restricted elements and HTTP(S) links, with a plain fallback. Recommendations are optional data, never automatic actions: review, explicit append or confirmed replacement, ordinary editable sequence snapshots, then explicit Run. Bind noisy sequences to the reviewed input, block stale/reset bindings, preserve clean comparison, and reuse MATLAB sequence progress/error/export handling.
